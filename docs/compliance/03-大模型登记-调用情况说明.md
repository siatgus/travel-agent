## 二、本应用与模型的职责边界

本应用是模型能力的**应用集成方**：负责需求理解、会话管理、外部数据整合、内容安全审核与结果呈现；生成能力完全由已备案模型承担，本应用不改变模型的生成机制。

具体调用链路：

```
用户输入 → 内容安全审核（输入侧）→ 通过 → 组装请求调用 DeepSeek API
       → 模型返回 → 内容安全审核（输出侧）→ 生成内容标识 → 呈现用户
       （输入侧命中则不发起模型调用，直接拒答）
```

## 三、关于"实质性修改"的立场说明（重要）

**主动说明事项**：本应用在模型输出侧执行了以下处理，特此说明其性质：

1. **内容安全过滤**（`moderation.sanitize_output`）：依据《生成式人工智能服务管理暂行办法》第十七条、《互联网信息服务深度合成管理规定》第十条，服务提供者**必须**对生成内容进行违法有害信息识别与处置。本应用的输出侧过滤系**法定义务性安全措施**：
   - 仅做关键词命中后的两类动作——删除/替换命中片段，或整条弃用并替换为固定兜底话术；
   - **不新增、不重组、不改编模型生成内容**，不改变模型输出的事实语义。
2. **结果呈现渲染**（`render_html.build_html`）：将模型输出的结构化行程数据（JSON 字段）渲染为网页排版。渲染对象是应用自身维护的数据结构，模型仅负责往其中填写文本字段；渲染过程不修改任何文本内容。

**结论**：上述处理均不构成对模型生成能力的实质性修改，本应用符合"调用已备案模型"的简化登记情形。如属地主管部门认定需升级为大模型备案，我司将按要求配合补办。

- 输入侧 + 输出侧双向审查（详见《内容安全管理制度》，材料包文件 01）；
- 本地关键词库（七类，含变体规避识别）+ 运营扩充词库热更新 + 云审核接口预留；
